# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository. Read it before changing anything. The README is the front page (what Ream is, installing, running, contributing, licence); `docs/` has the design notes (`design.md`) and deploys and releases (`deploy.md`); `CONTRIBUTING.md` is the short version of this file for people. This file is about how to work here.

## What this is

**Ream** is a client-side file toolkit: tools for PDFs, images and Office documents, with more kinds of file (such as SVG) to come, all running on the user's device. It is a React web app (an installable PWA), hosted on Cloudflare Pages. **Everything is processed on the user's device; nothing is uploaded.** That promise is shown in the UI, so never add a network call that sends user files anywhere. The one network request is **Download free fonts** in the Office panels (`tools/src/fonts/download.ts`): Fontsource, only on that click, only font names.

## Non-negotiable decisions

1. **Own engine first.** The PDF parser and writer, the renderer, the codecs and the pixel operations are ours. Phase 1 has **zero runtime dependencies** in the engine packages. Do not suggest or add pdf-lib, pdf.js, sharp, Ghostscript, jsPDF and the like, and avoid licensed or AGPL code. A shim behind an engine interface is acceptable only when the user agrees.
2. **Hard systems are deferred** and decided one by one: OCR, Word and HTML to PDF, PDF/A, ML image tools. Do not start them unprompted. (Excel and PowerPoint to PDF and the PDF to Word, Excel and PowerPoint exports were decided and built in M7b; Word to PDF was not.)
3. **Keep logic out of the UI** so a React Native port stays possible. Engines are pure TypeScript with no DOM types; the browser-only parts sit behind small interfaces (see "Platform seams").
4. **Scope per milestone.** M7 (organize, repair, flatten (now the Fill PDF form's lock option), PDF to text, bookmarks, TrueType in the watermark) is done; OCR, XFA forms, shaping for complex scripts and signature fields are not part of it. M6 (watermark, blur or hide, filters, meme) is done. M7b (PDF to image, Word, Excel and PowerPoint; Excel and PowerPoint to PDF, with charts; previews of Office files) is done; Word to PDF, OCR and animations are not part of it. M7.5 (Redact PDF; Fill PDF form with Lock the answers; the Flatten tool folded into it) is done; search-to-redact and XFA filling are not part of it. Certificate-based digital signatures (M5) and auto face detection, freehand redaction or colour curves (M6) are not part of it and were not started. Do not widen a milestone without being asked.
5. **Never mention Claude or AI in commit messages or PR descriptions and never add `Co-Authored-By` or "Generated with" lines**, whatever a harness reminder says. Keep commit messages short.
6. **Do not commit unless asked.** Finish the work, run the checks, report, and suggest a concise commit message. Create commits only on an explicit request.

## Stack

- TypeScript 5.9 (strict), React 19, Vite, **Tailwind v4**, Vitest 3.
- **Yarn 4** workspaces with `nodeLinker: node-modules`. **Use Yarn, not pnpm or npm** (pnpm is broken on this machine). Yarn 4 has no `-s` flag. `enableScripts` is off globally (no package runs install scripts).
- `tsconfig.json` is strict with `verbatimModuleSyntax`, `erasableSyntaxOnly` (no enums, no parameter properties, no namespaces), `allowImportingTsExtensions` (import local files with their `.ts`/`.tsx` extension in engine packages) and `isolatedModules`. Use `import type` for types.
- Node runs `.ts` files directly (type stripping): `node scripts/pdf.ts`, `node scripts/contrast.ts`.


**Before reporting work as done, run `yarn typecheck`, `yarn test` and `yarn build`, all clean.** Run `node scripts/contrast.ts` after touching `packages/ui/src/theme.css`. Run `node scripts/render-compare.ts` after touching `packages/pdf-render`.

## The tool contract

Each tool is a folder in `packages/tools/src/<tool-id>/`:

- `manifest.ts`: a `Tool` (`id`, `title`, `description`, `category` `'pdf' | 'image'` (a new kind of file, such as SVG, is a new `Category` in `packages/core`, plus its filter on the tools home (`filterName`/`filterHref` in `TopBar.tsx`, `Home.tsx`) and its group on the landing page (`Landing.tsx`)), `icon`, `accept`, `action`, `multiple`, `minFiles`, `preview: 'live' | 'manual' | 'size' | 'none'`, `status: 'ready' | 'soon'`). Register it in `index.ts`.
- `run.ts`: **pure bytes to bytes** `RunFn<Options>(files, options, { progress })`. It runs in a Web Worker in the app and directly in tests. No DOM, no React, no globals. Throw `UserError` (or a subclass) for anything the user can act on; any other error shows a generic message.
- `Panel.tsx`: the options UI, exporting `Panel` and `defaultOptions`. Panels receive `{ options, onChange, files, readMetadata?, readImageMetadata?, pdfHost? }`. They must not import from `apps/web`; anything they need from the app (page sizes, a rendered page, metadata) arrives through those injected props.
- Register `run.ts` in `runners.ts` and `Panel.tsx` in `panels.ts` (both lazy, so the UI bundle never pulls engine code). Constants used by both a panel and a run live in a **constants-only** module (for example `image-formats.ts`, `images-to-pdf/sizes.ts`, `rect.ts`) so panels do not import engine code, and `run.ts` does not import React.
- Shared helpers: `pdf-common.ts` (`loadPdf`, `pdfFile`, `selectPages`, `rgb`, `spotCentre`, `clampInt`), `image-common.ts` (`decodeFile`, `encodeFile`), `fields.tsx` (`inputClass`, `RangeField`, `SpotPicker`, `FormatFields`), `CropSurface.tsx` + `rect.ts` (drag-to-select).
- Option shapes are plain serialisable objects. Percentages and selections are stored as fractions so they do not depend on pixel sizes.
- `preview`: `live` and `manual` show the Original/Result pane. `size` (Compress PDF) runs the same live preview but shows only the new size beside the options (`SizeEstimate.tsx`); Run still reuses a fresh result. `none` has no pane: tools with their own surface (Crop image, Crop PDF, Sign) set `placesActions` and get the wide layout; the others (Edit metadata, PDF to Word) get files and an options card of readable width.

Current tools: merge-pdf, split-pdf, images-to-pdf, watermark, page-numbers, crop-pdf, metadata, extract-images, compress-pdf, protect-pdf, unlock-pdf, sign-pdf, resize-image, convert-image, rotate-image, crop-image, merge-images, compress-image, animated-gif, image-metadata, watermark-image, blur-image, filters-image, meme, organize-pdf, bookmarks-pdf, repair-pdf, pdf-to-text, redact-pdf, fill-pdf-form, edit-pdf, pdf-to-image, pdf-to-word, pdf-to-excel, pdf-to-powerpoint, excel-to-pdf, powerpoint-to-pdf.

To add a tool: manifest, run, panel, three registry entries, and tests. Reuse the helpers above.

## PDF engine notes (`pdf-core`)

- `PdfDocument.load(bytes, { password? })` parses everything up front (objects, xref streams, object streams, rebuild-by-scanning fallback). Encrypted files are decrypted at load (RC4 40/128, AES-128/256, user or owner password, empty password tried first). `doc.pages()`, `doc.pageSize(page)`, `doc.pageBox(page)` (box plus rotation), `doc.resolve()`.
- Writing goes through `PdfBuilder` (classic xref). `compose(parts, { info })` builds a new PDF from page selections and is the base of merge, split, rotate, stamp, crop and metadata. It deep-copies reachable objects and renumbers them. A `Part` can have `prepare` (runs **before** the page dictionary is copied; use it to prune what must not be copied) and `edit` (runs after, with builder objects).
- **Edits rewrite the file** (`compose`): bookmarks (`outline.ts`), form fields and named destinations that links use are carried over; tagged structure, layers, page labels and XMP are not. One `Importer` per source document is shared by all parts of `compose`, and every picked page is claimed before any is copied, so links can point at any picked page. A field survives when a widget of it is on a kept page (`Importer.copyField`).
- `editDocument(doc, change)` (`rewrite.ts`) is the other way to change a file: every object stays, `change` gets the catalog, `add`/`reserve`/`set` and `edit(ref)` (a private copy of one dictionary), and the result is written through `optimize({ tidy: true })`, so replaced parts (an old outline) are really gone. Bookmarks, Repair, Redact, Fill PDF form and `flattenPdf` use it.
- Forms: `readForm` gives each field's value (inherited `/V` included) and `widgets` (page, box as displayed fractions, radio state); `fillForm` changes only the fields it is given and refuses text over `MaxLen` and choices not offered. `terminalFields` adopts page widgets the form's `/Fields` doesn't reach (files whose form lists other copies), and `fillForm` points `/Fields` at them.
- `editForm(doc, { add, change, remove, order })` (`form-edit.ts`) makes, changes and removes form fields through `editDocument`. Places come in displayed points (bottom left), turned into user space with `displayedToUser`; a field on a turned page gets `/MK /R` and pictures with a turning `Matrix`. A change is found by name through `terminalFields` and keeps the keys it doesn't manage (other flags, actions); `redraw: false` keeps the widget pictures (a move). Removed widgets go through `pruneFields` (shared with Redact). `order` reorders a page's widgets inside `/Annots` and drops `/Tabs`. `readForm` also reports tooltip, required, alignment, size, colours and `dateFormat` (from an `AFDate_FormatEx` script).
- `decorate(doc, additions)` (`decorate.ts`) adds to existing pages through `editDocument`, so everything else is kept:
  - **Overlay:** a page of a PDF made with `buildPdf` is placed over a page as a form, with `displayedToUser` as its matrix; its objects are copied over once each.
  - **Annotations:** highlight, underline and strike-out (QuadPoints plus an appearance), notes with a pop-up, and links (URI or GoTo). Their places come in displayed points.
  - **Used by** Edit PDF. `PathStyle` has `blend: 'Multiply'` (the highlighter) and `round` ends.
- `readOutline`/`writeOutline`/`remapOutline` (`outline.ts`) work on plain `OutlineItem` data. `readForm`/`fillForm`/`terminalFields` (`forms.ts`) and `appearance.ts` read forms and draw field pictures (WinAnsi only); `flattenPdf` (`flatten.ts`, used by Fill PDF form's "Lock the answers"; there is no Flatten tool) uses them. `annot.ts` (`appearanceMatrix`, `normalAppearance`) is shared by the renderer and `flattenPdf`.
- `parseTtf`/`subsetTtf`/`prepareFont` (`ttf.ts`) embed a TrueType font for stamps: `prepareFont` is async (it deflates), its result goes in `Overlay.embedded` and is written once per file. `parseTtf(bytes, face)` picks a face of a `.ttc` by index or PostScript name, `woffToSfnt` unpacks WOFF 1, `fontFaces` lists a file's faces (family, style, PostScript name, embeddable). OpenType with CFF outlines is embedded whole (FontFile3/OpenType under CIDFontType0, CIDs are glyph numbers); CID-keyed CFF and CFF2 are refused. No kerning or shaping.
- `edit.ts`: `stamp` (draw on pages in *displayed* coordinates, rotation handled), `crop` / `cropBoxes` (displayed margins; `rewrite` makes it delete instead of hide), `setMetadata`. `images.ts`: `imagesToPdf`, `jpegInfo`. `text.ts`: Helvetica metrics and WinAnsi encoding for stamps. `info.ts`: /Info reading and writing. `content.ts`: `scanContent` (operators with byte ranges) and `usedResources`.
- `optimize(doc, { replace?, objectStreams? })` (`optimize.ts`) rewrites the *whole* document (unlike `compose`, it keeps bookmarks, forms and so on): reachable objects only, streams recompressed, identical streams/fonts/colour spaces merged (only types whose identity doesn't matter; never pages, annotations or optional-content groups), objects packed into object streams by `serializeCompact` in `writer.ts`. Pictures are swapped in through `replace` (old stream object to new one); the picture logic itself lives in `tools/src/compress-pdf/images.ts` and uses `imagePlacements` from pdf-render for the displayed size.
- Coordinates: stamps and crops are specified in the page **as displayed** (origin bottom-left, y up, `/Rotate` and crop box applied) and converted to user space inside the engine. Keep it that way and test rotated pages.
- `encryptPdf(doc, { userPassword, ownerPassword?, method?, permissions? })` (`encrypt.ts`) writes AES-256 (R6) or AES-128 (R4) protection; it reuses the password hashing in `security.ts`. Verify any change against an independent reader (pypdf in a throwaway venv: `python3 -m venv /tmp/venv && /tmp/venv/bin/pip install pypdf cryptography`).
- `stamp` can draw pictures: an `Overlay` may carry `images` made by `prepareImage` (compressed once, stored once per file however many pages use it).
- `build.ts` makes a PDF from scratch for the converters: a `PdfDrawing` of pages (`addPage(w, h)` -> `PageDraw` with `text`, `fillRect`, `line`, `path`, `clip`, `rotate`, `image`, in points from the top left, y down), `transform`, `save`/`restore`, `clipPath`; paths take `PathStyle` fills that can be gradients (shadings) and alphas), registered pictures (`ImageInput`, a JPEG goes in as it is) and `buildPdf(drawing)`. Text is the standard Helvetica, Times or Courier (`FontSpec.scale` squeezes the glyphs to stand in for a narrower font; `measure` uses the same scale) or a `FontFace` (`FontSpec.face`: one or more TrueType parts, such as a font's latin and cyrillic subsets); each string is split by the part that has each letter, falling back to the standard font, and every part is subset to what was drawn with it. Letters nothing has become `?` and are returned in `lost`. Tc and Tz are written on every text run because they carry over between text objects. Times widths are estimated from Helvetica's.
- Errors the user can act on extend `UserError` (`PdfParseError`, `PdfPasswordError`, `PdfRangeError`, `PdfEncryptedError`).

## Renderer notes (`pdf-render`)

- `renderPage(doc, index, ctx, widthPx, { platform, signal })` draws onto any 2D context (OffscreenCanvas in the preview worker). `Interpreter` runs content streams; it also has an `onOp` hook and an `analysis` mode (no image decoding) used by `bounds.ts` (`analyzePage`, `removeOutside`) with a recording context (`BoundsCtx`).
- Fonts (R3, done): glyphs are drawn as **paths from the embedded font program** at the exact PDF positions and widths. `outlines/` has the readers (`readTrueType`, `readCff`, `readType1`, `readProgram` for a descriptor's FontFile/2/3), all returning a `FontProgram` (glyph paths in font units, `matrix`, lookups by name, Unicode, built-in code, CID); `font.ts` picks the glyph for a code (`simpleShapes`, `cidShapes`) and gives `Font.shape`. Readers are bounded (subr depth, operator budget) and a glyph that fails is null: that letter falls back to a similar system font with `fillText` and the note "Some letters are shown with a similar font". Unembedded standard fonts use `Platform.standardFont` (the app installs Arimo, Tinos, Cousine with `installStandardFonts` from `@ream/tools/standard-fonts` in both workers). Analysis contexts (`pageChars`, bounds) never trace glyphs; a real canvas fills a cached `Path2D`. Text clip modes are collected per text object and clipped at ET. A see-through glyph that is filled and stroked (render mode 2 or 6) is stroked only outside its outline, so the stroke doesn't darken the fill (text knockout; the watermark's drawn bold relies on it). Test fonts are made in code: `makeTtf`, `makeCff`, `makeType1`, `glyphsOnly`/`glyphOf` in `pdf-core/test/ttf-helper.ts`.
- Text extraction: `Interpreter.onGlyph` reports each glyph with its place; `pageChars` (`textchars.ts`) collects them against a no-draw context, `layoutPage` (`textlayout.ts`) and `extractText` (`extract.ts`) turn them into text or Markdown. Heuristics; tested on synthetic characters and against pypdf.
- Structure for converters: `pageChars` also returns `shapes` (ruled lines and filled boxes, recorded from the interpreter's paths by `ShapeRecorder` in `shapes.ts`) and `pictures` (their boxes). `findTables` (`tables.ts`) finds tables from ruled lines (connected rules form a grid, a missing line merges cells) and from text that lines up (pieces cut at wide gaps, columns from the rows that have the usual number of pieces; two columns of long text are not a table). `pageBlocks` (`blocks.ts`) turns a page into paragraphs (runs with font name, kind, size, colour; alignment, indents, bullets, leading, space after), tables and pictures in reading order. Heuristics, tested on synthetic characters and on Chromium-printed pages. `rasterSize` / `browserRaster` (`raster.ts`) draw a page to pixels; tools take a `raster` parameter (default the app's) so `run` has no canvas types and tests pass a fake.
- Redaction (`redact.ts`, `redact-paths.ts`): `redactPdf(doc, areas by page in user space, { platform, hidden })` runs the analysis interpreter over each page with `record`. `onShow` reports each glyph of the recorded stream (TJ item, byte offset and length, advance `tx`, em-box corners), `OpInfo.ctm` gives the space of each path, and `onImage` (inline images too) the picture matrix.
  - **Text:** strings become `[kept -n kept] TJ`, with a removed letter replaced by a move as long as it was.
  - **Paths:** flattened, cut against the areas (fills: Sutherland–Hodgman against four disjoint regions outside each area, all in one path; strokes: Cyrus–Beck), clip geometry kept.
  - **Pictures:** raw samples are wiped bit by bit in place; JPEGs are decoded through the platform and stored as RGB Flate.
  - **New objects:** pictures and forms are new objects under new names, so shared originals are untouched and unused names are pruned so the originals leave the file.
  - **Annotations:** covered ones go, and fields left without widgets leave `/AcroForm`.
  - **Writing:** through `editDocument` (`keepInfo = false` drops /Info).
  - **Coordinates:** `displayedArea` turns a panel `Rect` into user space.
- Content editing (`content-edit.ts`): `pageContentItems` / `pageContentShares` read the page's own lines (glyphs from `onShow`, which now carries the text, font, font resource name, text matrix, CTM and colour, grouped by baseline, font and gaps) and pictures (page-level `Do` and inline images with their byte ranges). `fontLetters(font)` is the set of letters a font can show again (codes decoded, an outline that isn't empty or the .notdef's). `editContent` takes lines out with the Redactor in `centre` mode (text only, letters whose middle is in the line box), shows them again in their own font at the end of the page, takes moved pictures out and draws them again at the end (outside their clips), and erases areas with `transparent` (soft masks, not black). The Redactor's `RedactMode` picks what it removes.
- Standard fonts without `/Widths` (Helvetica, Times, Courier and their bold and italic): `standard-widths.ts` gives each letter the standard font's width, so the glyph boxes and advances every analysis reads (text boxes, redaction, content editing) are right without a canvas. Other fonts with no widths are still measured by the canvas, and the analysis contexts' stand-in measure is only an estimate (1 em a letter): never rely on it for positions of text in a font that has widths missing and isn't one of these.
- **Always look at rendered output, not just call logs.** Fake-canvas unit tests missed a y-flip bug and a stale canvas-font bug that only real pixels showed.

## Office files (`office-core`)

- `.xlsx`, `.docx` and `.pptx` are zips of XML. `unzip` / `zipPacked` live in `core` (the reader is bounded: entry count, sizes, a stream stops at its declared size; encrypted and ZIP64 are refused). `parseXml` drops namespace prefixes (`a:t` and `w:t` both read as `t`) and refuses DOCTYPE.
- Plain data models: `Sheet`/`Cell`/`Style` (`xlsx-model.ts`), `DocModel` (`docx-model.ts`), `Deck`/`Slide`/`SlideShape` (`pptx-model.ts`). `writeXlsx`, `writeDocx`, `writePptx` build the files; `readXlsx` (cells with their display text from `formatValue`, looks, widths, merges) and `readPptx` (placeholders resolved through layout and master, text styles by level, theme colours with tints, group transforms, table styles, backgrounds) read them. `tools/src/excel-to-pdf` and `powerpoint-to-pdf` lay the models out onto a `PdfDrawing`; `pdf-to-word`, `pdf-to-powerpoint` and `pdf-to-excel` build the models from `pageBlocks` / `findTables`.
- `readDocx` (`docx-read.ts`) reads paragraphs, runs, styles (`basedOn`, defaults), numbering markers, tables, inline and anchored pictures, text boxes, sections and page breaks; it feeds the Word preview only (`tools/src/docx-preview`), there is no Word to PDF tool. `readPptx` returns charts as `SlideChart` and `readXlsx` puts `pictures`, `charts` and `page` (the page setup, print area, title rows; `saved` is false when the sheet only has the margins every file has) on each sheet. `readChart` reads the cached values, or with a `ChartLookup` the cells a reference names (openpyxl saves no cache).
- Fonts: `tools/src/fonts/` is a seam like `PageRaster`. `FontBook(source, installed, uploaded)` loads faces for the text a file needs (`load(needs)`, then `spec(name, bold, italic)` for the builder): an installed font the panel found (`localFonts` option, from `window.queryLocalFonts()` in `InstalledFonts.tsx`), else a bundled look-alike with the same widths (`@fontsource` Carlito, Caladea, Arimo, Tinos, Cousine; WOFF read by `woffToSfnt`), else a standard font with `widthScale` from `office-fonts.ts`. `browserFonts` imports the WOFF files lazily through Vite; tests pass `nodeFonts`. Office runs take the source as their last parameter.
- Fonts panel (`fonts/FontsPanel.tsx`): lists `usedFonts`, uses installed fonts automatically when `local-fonts` is granted (close names through `closestFamily` in `fonts/match.ts`, embeddability checked in the worker with `readFontFile` -> `fontFaces`), adds font files (several, matched by name) and downloads free ones. Everything goes into the `localFonts` option as `InstalledFont` with `for` (the family it stands for) and `source`. `FontBook` picks by `for`, the slant and the nearest weight (no more than 150 away), several files of one style become one face. The builder writes `/ReamFamily` (the family the document asked for) on each embedded font, one resource per look-alike part and asked family; the renderer's `faceOf` reads it back, else the embedded font's family name, and maps Ream's look-alikes to their Office originals.
- PDF to PowerPoint uses `placedBlocks` (`pdf-render/src/placed.ts`), not `pageBlocks`: pieces cut at 1.5 em gaps, stacked by spacing, size and a shared edge, ruled lines between rows keep cells apart, lines kept with `breaks` (paragraph runs joined by "\n", box wrap off). `toLines` follows drawing order into runs, then joins runs on one baseline (within 0.15 em); never link characters by height across the page again (a big title chained the lines beside it and mixed their letters).
- Placeholders: a layout placeholder is found by idx, then type; a master placeholder by type only (a master's numbers are its own: a slide number can share idx 4 with a layout's content placeholder).
- Charts: `tools/src/office-charts.ts` (`drawChart`, `chartFontNeeds`) draws a `Chart` into a box on a `PageDraw`; PowerPoint and Excel to PDF both use it (Excel passes a white area with a grey edge as the default look).
- PDF to Word and PowerPoint keep the design as a picture: the page is rasterised with `leave: { text: false }` (`PageRaster`'s last parameter; the renderer's `text: false` skips glyphs), left out when `isBlank`, and editable text goes on top (Word: `wps` text boxes in front of the picture, because Quick Look fades pictures behind text).

## Platform seams

- Image codec: `codec()` / `setCodec()` in `image-core`. The app's worker sets `appCodec` (`image-core/browser`): the browser's native codec (OffscreenCanvas) where ours is many times slower (JPEG read and written, opaque PNG written, WebP), ours for PNG reading, see-through PNG writing (a canvas premultiplies alpha, so lossless would stop being lossless), GIF and BMP, and ours again whenever the browser fails. Native JPEG reading keeps samples as stored (`colorSpaceConversion: 'none'`) like ours; the browser's JPEG adds an sRGB profile, so Compress image keeps only its JFIF header and puts the file's own segments back. Tests call `setCodec(ownCodec)`; the native paths can't be tested in Node and are checked in Chrome. Decoders and encoders are pure and synchronous (`decodeJpeg`, `encodeJpeg`, `decodeGif`, `encodeGif`, `decodeBmp`, `encodeBmp`, `decodePng`, `encodePng`) and are used directly where the codec can't do the job (GIF frames, palette PNGs (PDF to image keeps ours for its pages: small files for text), grey JPEGs). Compress PDF reads colour JPEGs through `Platform.decodeJpeg` (the browser's, as the renderer draws them) and the rest with ours.
- Text on pictures: the engine has no font code. Panels draw text to a PNG with the browser canvas (`bitmaps.ts`: `textMark`, `pictureMark`, `trimmedPng`; `meme/caption.ts`) and put it in the options; `run.ts` only decodes and places it with `overlay`. Keep it that way; a Node test passes a ready-made PNG. `blur-image` is the one panel that imports engine functions (`apply.ts`): it shows the same operations on a 1400 px copy so the preview matches the saved file.
- Flate: `deflate` / `inflate` in `core` use `CompressionStream` (async); `inflate` keeps its output when bytes follow the end of the data (a stream Length that counts a line break), which the platform stream rejects.
- Renderer `Platform`: `imageFromRGBA` and `decodeJpeg`. Tests pass fakes.
- Page pictures: `PageRaster` (`pdf-render/raster.ts`), the last-but-one parameter of `pdf-to-image`, `pdf-to-word` and `pdf-to-powerpoint`'s `run` (default `browserRaster`: OffscreenCanvas); `extractFrom` takes a `Platform`. Tests pass fakes, real pixels are checked in the app.

## Web app (`apps/web`)

- Host calls for panels (`PdfHost`): `pages`, `outline`, `form` (`readForm`), `check`, `PdfPage`, `LazyPage`; each outline/form/check call goes panel, `ToolPage`, `previewClient`, `previewWorker`, pdf-core, like `readMetadata`.
- `ToolPage.tsx`: files | preview | options at `xl`; at `lg` the options stay on the right with the files above the preview; stacked below that, options before the preview. Options are always the right-hand region. Tools with their own surface (crop, sign) set `placesActions` and render the `actions` prop (run button, progress, errors) beside their controls. A finished run opens a modal `<dialog>` (download, keep editing, start over, use in another tool), not a card under the options. Locked PDFs open a password dialog and are replaced by a decrypted in-memory copy; the password is never stored.
- `previewController.ts` (pure, fake-timer tested) runs the same engine as the Run button: **600 ms debounce**, cancels stale runs, keeps the last result on screen. `ready` states have `stale` (outdated; Run never reuses a stale result) and `computing` (dim and "Updating..."). Do not make the UI react per keystroke.
- `previewWorker.ts` / `previewClient.ts`: one worker for inspect, render, unlock and metadata. The main thread never parses a PDF. Page canvases keep the old picture until the new one is ready (no flashing).
- Tool runs go through `runtime.ts` and `worker.ts` (progress, cancel, ZIP for several outputs). Limits: 50 files, 200 MB per file, 500 MB total. One tool worker is kept warm between runs (`warmTool` loads the engine when a tool page opens; a run that starts while it's busy gets its own worker; cancelling terminates it). Each input carries a `key` (the same `File`, the same key), and `decodeFile` keeps decoded pictures under it (up to 512 MB, only for the current inputs), so a preview after an option change doesn't decode again. Run functions get a copy: they may change their pixels.
- Office files preview as PDFs: `previewClient` sends the kind with the bytes (`officeKind` in `usePdfInfo.ts`, kept free of engine code), `previewWorker` converts once with `officeToPdf` from `@ream/tools/office-preview` and then inspects and draws it like a PDF, adding an "approximate" warning. `isPreviewable` (PDF or Office) decides what `Preview` and `Thumb` show.
- Zoom: `ZoomBar`, `useZoom`, `zoomedWidth`, `renderWidthFor` and `useWidth` live in `@ream/ui` (`Zoom.tsx`). The Original/Result pane starts at fit width, with its `ZoomBar` (Fit width and Fit page) on the tabs row: `Preview` owns the zoom and `PdfView` reads it from `ZoomContext` and reports the size shown (no bar for pictures or text); panels that work on one page (Crop PDF, Sign PDF, Redact PDF, Fill PDF form) use `usePageZoom` (`tools/src/PageZoom.tsx`), which starts with the whole page in view and also offers Fit width. A zoom is a share of the actual size (a point is 4/3 CSS pixels), the page box is sized in CSS pixels inside a scrolling area, and everything drawn over it is positioned in fractions, so overlays scale with it. Pages are re-rendered at the shown size (in 200 px steps, at most 4000).
- Edit PDF (`tools/src/edit-pdf`):
  - **Items:** `items.ts` holds them as plain data, with fractions of the displayed page like other tools.
  - **Saving:** `draw.ts` turns them into a `PdfDrawing` (text with `FontBook` faces, wrapped by `wrapLines` in `layout.ts`) and annotations for `decorate`.
  - **Page view:** `Overlay.tsx` draws the items over the page (SVG for shapes, HTML for text and pictures) and handles every gesture.
  - **Same lines on screen and in the file:** text in the editor uses the same font files through `FontFace` (`viewFonts.ts`) and the same `wrapLines`, measured with canvas, kerning off.
  - **Undo** lives in panel state, not in the options. Shortcuts listen on the window while the editor is open.
  - **Text for markup** comes from the `chars` host call (letter boxes from `pageChars`), made into the page as it is now by `liveChars` (`content.ts`: changed lines where they are, added text laid out like the editor draws it); `pickText` (`geometry.ts`) picks letters the drag covers by at least half, over their capital-height band, and gives a quad per run, trimmed where lines meet.
  - **Tests:** `geometry.ts` (move, resize, snap, pick text) is pure and tested.
  - **Form fields mode:** a `FieldItem` is one widget; a field shown in several places (a radio group) is the items that share a name, and `updateField` keeps its settings the same on all of them. The file's fields load through the `form` host call (`fieldItems`) and are kept in `fieldsLoaded`; `formEdits` (`fields.ts`) compares the two and gives `editForm` what changed, before `decorate` runs. The page is drawn without its own fields (`PdfPage fields={false}`, the renderer's `fields: false`) so the editor's boxes are the only ones shown.
  - **Find fields:** `detect.ts` (pure, tested) works on the `layout` host call (letters and ruled lines in points from `pageChars`).
  - **Edit content mode:** the `content` host call gives the page's lines and pictures; picking one makes a `LineEditItem` or `PictureEditItem` (deleting marks it `deleted`, so it can be put back), and the Erase tool makes `EraseItem`s. `contentEdits` (`content.ts`) turns them into `editContent`'s input plus what is drawn over the page instead (a line its own font can't show, as a `TextItem` on its old baseline; a replacement picture). The run goes `editForm`, `editContent`, `decorate`.
  - **What the editor shows:** the page is drawn *without* what was changed (`PdfPage hide`, the renderer's `hide`: letters and pictures whose middle is in a changed item's old box, the same test the saved file uses; erased areas as an even-odd clip), so there are no cover boxes. Everything is stacked in the saved file's order (`layerOf` in `geometry.ts`: the page's own content and changes, then added items in list order, then comments, then fields) with a z-index per item; page lines and pictures can be picked with Select in Add to pages too, under whatever was added over them. `stepOrder` / `canStep` move an item past the next one it overlaps in its layer.
  - **Fonts:** the `fonts` host call (`documentFonts` in pdf-render) lists the PDF's families for `FontsPanel`, whose choices go in `o.fonts`. A changed line its own subset can't show is drawn in its family (`fallbackFont`), so the font book uses a font added for it or the look-alike; `viewFonts.loadFont` mirrors that in the editor.
- Routes (`App.tsx`, hash based): `#/tool/<id>` the tool page, `#/tools`, `#/tools/pdf` and `#/tools/image` the tools home for a category (`Home.tsx`, `filterHref` in `TopBar.tsx`), `#/licence` and `#/notices` (`Legal.tsx`: the repo's `LICENSE` and `THIRD-PARTY-NOTICES.md`, imported `?raw` when the page opens) and `#/` (`Landing.tsx`); any other hash shows the landing page. The web-only pages share `Marketing.tsx` (nav, footer, `primary`/`secondary` link styles); app pages render `TopBar` (logo on the left; search and theme on the right; 1600 px like the pages) and `Breadcrumb` under it (All tools, the category, the tool; every level a link). The breadcrumb replaces visible headings on the tools home and tool pages (the `h1` is `sr-only`); on All tools the PDF tools and Image tools section titles link to their category. `focus` in `TopBar.tsx` is the shared focus ring.
- Tools home (`Home.tsx`, at most 1600 px wide) is drop-first: the `Dropzone` `bar` layout, and dropped files handed to a tool through `handoff.ts`, the same mechanism as "Use in another tool".
- Docker: `Dockerfile` builds the site with Node (on the build machine's platform) and serves it with `nginxinc/nginx-unprivileged` (non-root, port 8080). Its NGINX site is generated from `apps/web/public/_headers` by `scripts/nginx-conf.ts`, so change headers there only. The image build skips the typecheck (tests are left out by `.dockerignore`; CI typechecks anyway). `check` builds and runs it and checks the page, the headers, `sw.js` not being cached, the manifest's type, a 404 and a non-root user; the release pushes amd64 and arm64 images to `ghcr.io/deityhub/ream` and, with `DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN` set, `docker.io/<user>/ream`, tagged with the version and `latest`. Containers can't start in this Mac's Docker; test a server inside a throwaway `docker build` (start it in a `RUN`, query it with curl) or rely on CI.
- Versions: the root `package.json` `version` (semver, starting at 0.1.0) is the release version. A pull request into `main` must raise it and have its `CHANGELOG.md` section: `yarn release patch|minor|major` (`scripts/release.ts prepare`) writes both, the section from the pull requests merged since the last tag (first-parent merges of `dev`, their titles and links; earlier releases skipped), and `node scripts/release.ts check` fails on a version already tagged or older or one without a section. The merge deploys production, tags `v<version>` and creates a GitHub Release whose notes are that section (`release.ts notes`). `.github/workflows/prepare-release.yml` (Actions → Prepare release) runs `prepare` on `dev` and opens the "Release v<version>" pull request into `dev`, as the `RELEASE_TOKEN` secret so `check` and the preview run on it. The version is in the footer (`__APP_VERSION__`, defined in `vite.config.ts`, declared in `version.d.ts`) and in the offline cache's name. `.github/workflows/deploy-version.yml` builds a released tag again and deploys it to production (rollback when the Cloudflare dashboard's can't).
- Hosting: Cloudflare Pages, deployed by `.github/workflows/web.yml`: a pull request into `dev` runs `check` and gets a preview (its link is commented on the PR), a pull request into `main` runs `check`, a merge into `main` runs `check` and deploys production. Plain pushes run nothing. `check` is the status `.github/rulesets/protect-dev-main.json` requires (import it under Settings → Rules once the repo is public: rulesets aren't free on private repos). `apps/web/public/_headers` holds the security headers: the CSP allows only the site's own files, plus `api.fontsource.org` and `cdn.jsdelivr.net` in `connect-src` for Download free fonts, and no inline scripts or styles (`style-src 'self'`: React's `style` props are fine, `<style>` elements and `style="..."` strings are not). A new network host or inline style needs the policy changed, and the user asked first (the network rule above). Check with `wrangler pages dev` and a `securitypolicyviolation` listener.
- PWA: `manifest.webmanifest` and `icons/` in `apps/web/public` (PNGs from `apps/web/icons/icon.svg` by `node scripts/icons.ts`; square, full bleed, the mark inside the maskable safe zone). `apps/web/sw.js` is plain JS, outside `src`: the `serviceWorker` plugin in `vite.config.ts` writes it into `dist` after the build with every file's name (minus `.woff` fallbacks and the non-Latin Office fonts, which it keeps when first used) and a version hashed from their contents. The page is kept as `./` because Pages redirects `index.html` to `/`. Navigations are network first, everything else cache first. A new version waits until the user clicks Reload in `UpdateBar.tsx` (`pwa.ts` posts `switch`; the page reloads on `controllerchange` only after that, since the first worker's `clients.claim` changes the controller too). `pwa.ts` also keeps the `beforeinstallprompt` event for the landing page's Install Ream button. The worker is registered in production builds only: `yarn dev` has none. To test offline for real, serve the build with `wrangler pages dev`, let the worker fill its cache, then stop the server (CDP's offline emulation doesn't reach the worker's own requests).

## Design system

- **System**: Industry (paper ground, one steel accent, square hairline objects with "+" corner marks, condensed headings). `packages/ui/src/theme.css` holds its ramps (`--color-steel-*`, `--color-neutral-*`) and the semantic tokens; light is Industry's, dark is derived (deep steel ground). Industry's base steel and 55% muted ink fail 4.5:1, so the tokens use the 700 steps; keep it that way.
- **Palette**: components use **semantic tokens only** (`bg-canvas`, `bg-surface`, `bg-surface-2` for inputs and raised rows, `text-ink`, `text-muted`, `bg-accent`, `bg-accent-soft`, `text-accent-ink`, `border-accent-2` for hover edges, `border-line` for hairlines, `border-field` for input borders, `text-success`/`bg-success-soft` (steel: the scheme is mono), `text-danger`, `bg-danger-soft`, `text-warning`, `hover:bg-ink/7` for tinted hovers), never ramp colours or hex. Cards and figures have no fill of their own. Light and dark come from `light-dark()`; `data-theme` overrides the system setting.
- Contrast is enforced: text 4.5:1, icons and input borders 3:1. `node scripts/contrast.ts` must pass.
- Fonts are Barlow (`font-sans`) and Barlow Condensed (`font-heading`: h1-h4 get it in `index.css`, buttons and titles use it), bundled through `@fontsource/barlow` and `@fontsource/barlow-condensed` (works offline; never load fonts from a CDN). Numbers take `tabular-nums`, not a monospace font.
- Shape: everything is square (`--radius-*` are 0, so `rounded-*` does nothing; `rounded-full` is kept for dots only, never for chips or pills). Cards, figures and the primary button wear the frame: `blueprint border border-line` (`Card` and the primary `Button` already do). The marks reach 5 px outside the box, so a framed element must not clip (`overflow-hidden`) and needs gaps of at least 20 px (`gap-5`) beside it. Shadows only for dialogs (`shadow-lg`, Industry's elevation).
- Icons are Lucide's shapes at stroke 1.5 in `Icon.tsx` (ISC notice at the top); add new ones from Lucide (`lucide-static` has the SVGs) rather than drawing them.
- Interaction rules: visible focus rings on everything (`focus-visible:outline-2 focus-visible:outline-accent`), `cursor: pointer` is set globally in `index.css` for enabled buttons, links, selects, checkboxes, radios, sliders and labels that hold them (`not-allowed` when disabled), 44 px touch targets on coarse pointers (`pointer-coarse:`), transitions respect `prefers-reduced-motion`, no emoji as icons (icons are inline SVG in `Icon.tsx`), no horizontal page scroll at 375 px.
- `fieldset` has `min-width: 0` globally; keep label rows `flex flex-wrap` so selects cannot overflow the inspector (18 rem wide).
- Logo: the "split sheet" mark (`Logo.tsx`, `apps/web/public/favicon.svg`, `apps/web/icons/icon.*` as the source of the app icons).
- Copy: sentence case, plain words, say what happened and what to do, no "please", no exclamation marks, no raw exception text.

## Testing

- Vitest, no DOM environment: engines and tools are tested in plain Node. Tool tests call `run()` directly with `FileData`.
- Fixtures: `packages/pdf-core/test/fixtures/` (`chromium.pdf`, `cups.pdf`, encrypted files made by pypdf with user password `user123` and owner password `owner456`). `packages/pdf-core/test/helpers.ts` has `assemble`, `formPdf` (every field kind) and friends for hand-built PDFs, and `ttf-helper.ts` makes a tiny TrueType font in code; `packages/pdf-render/test/helpers.ts` has `onePage`, `fakeCtx`, `fakePlatform`.
- Add tests with every change: engine logic, error messages, and rotated pages for anything that places things on a page. Prefer a test that fails if the logic breaks over many shallow ones.
- Independent verification matters because our parser, writer and renderer could agree on the same mistake. There is no qpdf, mutool or Ghostscript here. Use Chromium's PDF viewer (see below) and pypdf-made fixtures as oracles. macOS `sips` mishandles `/Rotate`, `/CropBox` and annotation appearances, so never trust it for those.
- Office files: python-docx, python-pptx and openpyxl in a throwaway venv (`python3 -m venv /tmp/venv && /tmp/venv/bin/pip install python-docx python-pptx openpyxl`) read what we write and make what we read (`packages/office-core/test/fixtures/` has a deck from python-pptx and a workbook from openpyxl). macOS Quick Look (`qlmanage -t -s 900 -o out file`, or `qlmanage -p -o` for an HTML preview of every slide) renders docx, xlsx and pptx as a second reader but ignores table cell margins, transparent text and Word frames, fades pictures behind text, and can't draw custom shapes, many presets or charts; check those against files whose contents you made. PDFs made from Office files are looked at in Chromium's viewer (`#page=N` for each page) and their text extracted with pypdf. Chromium's `printToPDF` from HTML is the oracle for tables and paragraphs going the other way: the HTML is the ground truth. Nothing has been opened in Microsoft Office; say so.
- Codecs are checked the same way: Chromium decodes the files (`createImageBitmap` for JPEG/PNG/BMP, `ImageDecoder` for every GIF frame; both need a `file://` page, `data:` pages are not a secure context) and the result is compared with ours; our encoders' files must decode in Chromium. macOS `sips` makes baseline JPEG, GIF and BMP test files (and CMYK ones with `-m` and a CMYK profile). There are real progressive JPEGs and GIFs on most machines (`mdfind`). Keep personal files out of fixtures and out of what you print; use them only as local oracles.

## Style

- Match the surrounding code: comment density, naming and idiom. Comments explain *why* (limits, gotchas, reasons), not what.
- Mark deliberate shortcuts that have a known ceiling with a `ponytail:` comment naming the ceiling and the upgrade path.
- Small files, one folder per tool, no abstractions without a second user, no config for values that never change.
- Pixel loops are hot (a phone photo is 12 to 50 million pixels): no allocation per pixel (`data.set(src.subarray(i, i + 4))`, array literals, destructuring), write the four bytes; walk memory in row order (a column at a time misses the cache); compare against the old code's output when speeding something up. Measure with a 12 MP photo and a few hundred pages before and after.
- Prefer the platform (CSS, native elements) over code, and the standard library over dependencies. Do not add runtime dependencies to engine packages. UI-only asset packages (fonts) are fine. Ream is MIT: anything shipped must be MIT-compatible (no GPL, AGPL or LGPL), and adding, removing or updating a runtime dependency means running `node scripts/notices.ts`. Code copied in by hand (like Lucide's shapes) keeps its notice in the file and gets an entry in `scripts/notices.ts`.
- Do not put personal data in URLs, logs or tests.

## Workflow expectations

- For a feature, read the surrounding tool folders first and reuse the helpers above. For a bug, find the root cause (grep every caller) and fix it once where all callers route through.
- Big or ambiguous changes: plan first, name the files, and ask about decisions that change behaviour (the user likes to see design options before committing to one).
- After a change: typecheck, tests, build, then verify visually in the app for anything with UI. Report what was verified and what was not (Safari, Firefox and touch input have not been tested; only Chrome has).
- Leave changes uncommitted unless asked; offer a concise commit message.
